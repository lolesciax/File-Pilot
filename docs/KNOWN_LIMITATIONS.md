# Known limitations

- Browser-local memory and native canvas encoders determine practical limits. PDF operations use a worker; image decoding/encoding and images-to-PDF creation can briefly occupy the main thread. OffscreenCanvas is not currently used.
- Inputs: 100 MB each, 300 MB per selection, 100 files; PDFs: 2,000 pages. Images: 50 million source pixels, 32 million output pixels and 8,192 pixels per output edge. PDF image export caps generated content at 300 MB. These are safeguards, not a guarantee every device can process the maximum.
- Password-protected PDFs are rejected; no password removal or protection bypass. Malformed/unsupported PDFs may be rejected. pdf-lib modification may discard digital signatures, outlines, source metadata, interactive forms or document-level features; check important documents before relying on output.
- Image conversion supports JPEG, PNG and WebP only. SVG, GIF, HEIC, TIFF, OCR, AI upscaling and arbitrary PDF text editing are unsupported. Animated PNG/WebP inputs, if decoded by the browser, are flattened to a static image. Image metadata is not preserved.
- Office conversion supports DOCX/XLSX/PPTX inputs and PDF↔modern Office outputs. Legacy DOC/XLS/PPT, macro-enabled files and password-protected Office packages are rejected. Office content and supported layout are converted, but font substitution, unsupported charts, drawings, animations and complex formatting can change the result. Conversion notes expose reported losses; absence of a reported loss does not guarantee exact fidelity.
- PDF→DOCX is editable reconstruction, not pixel-identical layout restoration. PDF→XLSX extracts selectable text into inferred rows/cells with one sheet per selected page; it does not recover formulas, exact table structure or charts. PDF→PPTX creates a page image per slide; text and shapes are not editable objects. Scanned/textless PDFs cannot become editable Word/Excel without OCR and are rejected by those tools. PDF page images can still become PPTX slides.
- Office inputs: 20 MB compressed, 80 MB expanded, maximum 2,000 ZIP parts. Office output/selection is limited to 200 pages; worker operations time out after 90 seconds and can be terminated by cancellation. Office→PDF uses local Liberation Sans substitutes and rejects unsupported glyphs (e.g. many CJK scripts) instead of downloading fonts. Excel uses stored workbook print layout/values and does not refresh external data or execute macros.
- PDF→XLSX extracts at most 100,000 cells, 512 columns, ten million text characters and 32,767 characters per cell. PDF→PPTX renders at most 60 MB of PNG content; the first selected page sets the common slide aspect ratio, with other page sizes contained and centered. PowerPoint slide dimensions must be 1–56 inches. These guards are additional to the normal input/output memory limits.
- Office package structure and content are checked with controlled fixtures and the independent PDF/Office readers used in tests. Desktop Microsoft Word/Excel/PowerPoint and LibreOffice interoperability, large real-world Office documents and complex multilingual layouts remain unverified. Review important documents after conversion.
- PNG canvas export is lossless re-encoding, not advanced PNG optimization. File size reduction is never guaranteed. Original retention can preserve the original format when compression offers no benefit.
- Contain resize creates the requested canvas dimensions with letterboxing; PNG/WebP may keep transparent padding, JPEG uses the chosen background. Cover crops edges. Stretch explicitly distorts proportions.
- Browser-based batch rename downloads copies; it cannot rename arbitrary originals on disk. Filename cleanup removes unsafe characters; output extensions are preserved. Numbering is three-digit minimum width.
- Cancellation interrupts PDF workers immediately, and checks image/raster batches between items; native operations already underway complete first. ZIP export runs asynchronously and cancellation is observed after packaging. Validation has no cancel control.
- Active source-file selection is shared for the current tool. Switching to a different tool starts a fresh input selection; refresh/close loses the session. Tool options are remembered only in this tab. Theme is the only persistent preference. There is no processing-history database or offline/PWA cache.
- Saved downloads retain only the latest batch per tool. A new run, replacement input selection or Process Another File discards that tool's prior results; download them first. Failed-file retries extend the current batch. Other tools' saved downloads remain until replaced or cleared. Review files and settings preserves the current batch. Completion replaces the editor and adjusts window scrolling only when needed to expose its heading/icon and download action. There is no floating download bar.
- Crop is a rectangular selection with movement, corner resizing, numeric fields, keyboard movement, fixed/custom ratios and selection zoom. Image-to-PDF uses contain sizing, not cover cropping.
- Full processing regression coverage uses installed Chromium. Responsive route/layout, loaded-workspace and touch-interaction checks also run in Playwright Firefox and WebKit on Windows; these engines do not substitute for physical Safari/iOS/Android testing. Real devices, actual maximum-size documents and complete manual screen-reader conformance remain unverified. Automated accessibility scans do not establish full WCAG conformance.
- No actual Cloudflare deployment or live header verification has been performed. The production preview plugin applies the configured global headers locally; those headers and all processing workflows are exercised in production-mode tests.
