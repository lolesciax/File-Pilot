# Architecture

Office conversion extension: `reamkit` is the only additional runtime library (its XML parser is transitive). It runs in a lazy ES module worker, using bundled Liberation Sans variants. No provider, backend, license key or document upload is involved. Ream performs DOCX/XLSX/PPTX→PDF and PDF→DOCX reconstruction; PDF.js extracts selectable text or rasterizes PDF pages for XLSX/PPTX export. A small OOXML package writer reuses fflate for literal-text worksheets and image slides, avoiding additional spreadsheet/presentation dependencies. Legacy Office, macros, encrypted packages and unsafe/oversized ZIPs are rejected.

Library integration references: [Ream getting started and explicit font supply](https://reamkit.dev/guides/getting-started/), [Ream scope and limitations](https://reamkit.dev/guides/scope/). Application fidelity claims are limited to tested behavior, rather than adopting the library's full advertised format coverage. Browser font loading uses the locally bundled PDF.js font resources.

Static React SPA with React Router. Home/catalog and settings load immediately; tool workspace and processing libraries load on demand. Zustand stores files, results, jobs, and theme preferences. File objects remain in memory; only theme is saved in localStorage. No network request carries document contents.

`src/processing` owns validation, PDF manipulation, canvas transforms and asynchronous ZIP generation. `src/features` composes tool configuration and shared previews. `src/components` provides shell, upload and Radix dialog primitives. Processing reports completed units, checks AbortSignal between units, preserves partial batch results, and never mutates source files. PDF.js uses a bundled worker. ZIP compression uses fflate's asynchronous worker API.

Routes: `/`, `/tools`, `/tools/pdf`, `/tools/image`, `/tools/batch`, `/tool/:id`, `/workspace`, `/settings`. Active session survives route changes and is lost on refresh/close. No authentication, backend, remote fonts or required secrets.

Source selection belongs to the active tool. Zustand tracks output IDs and errors/cancellation per tool alongside saved blobs. A new run, replacement selection or Process Another File releases that tool's previous batch; retries append only their successful outputs to the same batch. Other tools' latest batches survive navigation and are available in Saved downloads. There is no accumulating conversion history. Output names are made unique within each batch, and ZIP packaging resolves collisions across saved batches. Options are held per tool in the tab session. PDF thumbnail blobs are cached with a bounded per-file cache; source keys are weak references. Image batches show queued/processing/completed/failed/cancelled states and can retry failed entries. PDF source validation currently uses pdf-lib on the main thread; expensive output construction uses a worker.

All tools use `ProcessingAction` for Ready/Processing/Failed and `CompletionScreen` to replace the entire editor when valid outputs are available. A typed message map covers every tool; download labels reflect the actual output extension. `Results` supplies shared file metadata, per-output conversion notes, downloads, ZIP packaging and a bounded expandable batch list; the standalone workspace reuses it for Saved downloads. Partial/cancelled jobs show a warning state and recovery controls, with outcomes retained alongside the batch across navigation. Empty/malformed output cannot trigger success. Completion focuses its heading and adjusts only the window scroll when its icon/download would be outside the viewport. The old floating download bar is removed. Process Another clears the current batch, source selection, page edits, job status and source-specific ranges; other preferences remain. Review files and settings preserves results until a new run. Preview components unmount/revoke image URLs, and option-size observation reconnects when returning to the editor.

Configuration references checked during implementation: [Vite guide](https://vite.dev/guide/), [Tailwind Vite integration](https://tailwindcss.com/docs/installation/using-vite), [PDF.js setup](https://mozilla.github.io/pdf.js/getting_started/). Installed PDF.js TypeScript definitions were checked for its current loading-task cleanup API. Dependency versions are locked in package-lock.json.
